# Vercel 测试部署说明

> **仅用于测试，不推荐用于实际生产环境。** PacPilot 的正式部署方式仍然是 Docker / Docker Compose。Vercel 方案主要用于临时预览、界面联调和功能验证，不应作为长期、稳定或承载真实用户数据的生产部署。

本文是仓库内 Vercel 测试部署相关约定的唯一集中说明。修改 Vercel 测试部署时，请优先更新本文；根目录配置和 Vercel 必需入口只保留平台要求的内容。

## 范围与限制

- `vercel.json`：Vercel 必须从仓库根目录读取的构建输出和路由重写配置。它不是通用生产部署配置。
- `api/index.ts` 与 `api/[...path].ts`：Vercel Functions 必需的路由入口，统一转发到 `server/vercel-handler.ts`。
- `server/vercel-handler.ts`：测试部署专用的 serverless 适配层。不要把 Vercel 专属运行逻辑扩散到业务路由或服务中；通用业务逻辑应继续放在现有 server 模块。
- Vercel 相关文档、约束和维护说明集中放在本文件。不要在其他文档复制一份详细部署流程。

## 与正式部署的区别

正式部署请使用 [Docker 部署指南](deployment.md)。Vercel 测试方案存在以下限制：

1. 运行环境使用内存存储（`STORAGE_DRIVER=memory`），实例重启、冷启动或请求落到不同实例时，状态和数据不保证持久或一致。
2. 不应将其用于需要可靠持久化的管理员凭据、配置、工作流记录或 PAC 文件。
3. Serverless 实例的生命周期、并发和资源限制不同于常驻服务；定时任务及依赖进程内状态的行为不能据此视为生产可靠。
4. 能够构建或打开页面不等于完整验收。使用前应单独验证 API、认证、状态一致性和关键用户流程。
5. 不要在 Vercel 测试项目中存放真实生产凭据或敏感数据。测试用环境变量应与正式环境隔离。

## 维护约定

- Vercel 配置只用于测试预览；不要据此把 Vercel 宣传为 PacPilot 推荐或受支持的生产部署方式。
- `vercel.json` 必须留在仓库根目录，这是平台约定；Vercel Functions 的 `api/` 入口也必须留在平台识别的位置。因此，这些少量平台入口无法全部移动到单一子目录，但实现细节和说明应尽量集中。
- Git 关联、自动部署分支、项目保护、域名和环境变量属于 Vercel 项目设置；更改时必须确保目标仍是独立测试项目，并且不能将 `dev` 的测试部署当作生产发布。
- 本文是仓库内测试部署说明的唯一详细文档。变更 `vercel.json`、`api/` 入口或 `server/vercel-handler.ts` 时，请同步检查本文和相关测试；不要为此改动 Docker 正式部署路径。
