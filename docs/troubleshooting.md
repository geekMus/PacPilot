# 故障排查

## 无法访问网页

- 确认容器正在运行：`docker ps`
- 确认已发布端口：`docker port genpac-runner`
- 查看服务日志：`docker logs --tail 200 genpac-runner`
- 检查宿主机防火墙、反向代理和端口映射。
- 确认访问的宿主机端口与 Docker 的端口映射一致。

## 管理员无法登录

- 查看首次启动日志中的随机密码：`docker logs genpac-runner`。
- 若密码遗失，按[配置说明中的管理员密码重置步骤](configuration.md#管理员密码重置)重置。
- 确认重置脚本使用的是服务实际使用的数据目录。

## PAC 仍是全量直连

- 新数据库首次启动不会自动生成 PAC。
- 在后台启动生成，并在工作流页面确认结果成功。
- 检查生成模式、代理地址、自定义规则和远程列表的可访问性。
- 生成前访问 `/proxy.pac` 可能返回临时的全量直连脚本，这不代表配置已经生效。

## 远程列表生成失败

- 确认容器能够访问配置的 URL。
- 确认内容属于支持的列表格式：GFWList（Base64）、域名型 AutoProxy / ABP，或每行一个域名的纯文本列表。
- 该功能不是完整的 ABP 规则引擎，复杂过滤表达式可能不会按原意处理。

## 升级后配置丢失

- 检查容器是否始终挂载到同一个持久化卷或数据目录。
- 没有挂载 `/data` 时，删除容器可能导致应用数据丢失。
- 不要在需要保留数据时删除 Docker 命名卷；升级前请备份数据库和 PAC 文件。

## 跨域管理 API 请求失败

- 默认不开放跨域浏览器访问管理 API。
- 仅在前端确实部署于其他 Origin 时配置 `CORS_ALLOWED_ORIGINS`。
- 检查 Origin 是否完整匹配白名单中的来源，且不要使用通配符。
- 参考[配置说明中的跨域与访问安全](configuration.md#跨域与访问安全)。
